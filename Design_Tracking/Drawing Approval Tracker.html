      The review cycle

      Each drawing goes back and forth between the department that drew it and Engineering until it is approved. Every pass is saved as a new revision, so nothing is overwritten and the full history stays visible.

      DesignSubmit R0Department uploads the drawing for a floor, with drawing number and title.
      EngineeringReviewEngineer marks up the drawing and records each issue as a numbered comment.
      EngineeringDecideApprove, or return with comments. A return sends it back to Design.
      DesignRevise and resubmitDesign answers every comment, uploads R1, R2 and so on. The old revision is stamped Superseded.
      BothApproved → Issued for constructionOnly the latest approved revision can be issued to site.

      Steps 2 to 4 repeat until the drawing is approved. The dashboard counts how many rounds each drawing took and how long each side held it.

      RecordHolds
      Project → Building → FloorThe structure, so drawings can be grouped floor by floor (B1, Ground, 1–10, Terrace)
      DepartmentArchitecture, Structural, Plumbing, Electrical, HVAC, Fire fighting; each has a design owner and an engineering reviewer
      DrawingNumber (e.g. TA-STR-F03-01), title, floor, department, current status, who has it
      RevisionR0, R1… with the file, submitted by/on, reviewed by/on, decision
      CommentNumber, text, markup location, Design’s response, open or closed
      Activity logEvery submit, return, approval, download and view, with person and time

      This sits on top of the document system already analysed: floors become folders, departments map to document types, and drawing number, floor and revision become fields.
